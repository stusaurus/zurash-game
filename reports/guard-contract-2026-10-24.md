# B戦術判定の独立監査（2026-10-24）

PR #15の `02d33cf0e8161f90bc68cb7d998d1951451378be` を基点とする補足検証。研究用の得点経路・即負け回避・3手以内必勝判定に、今回の範囲で不一致はなかった。新たなCPU強化や公平性改善は認定しない。正式盤面・ルール・本番CPU・キャラクター画像の変更は0。SprintとA〜Eを維持する。

## 問題と今回追加した仕組み

既存研究ではBの防御手がbeam8の外へ落ち、研究用retainが安全候補を残すよう修正されている。しかし、対戦成績が改善しても「安全」「3手必勝」の判定自体が間違っていれば根拠にならない。保存された代表局面だけでなく、固定した小盤面の配置全列挙と、既存17局面の全件を、独立した合法手生成で照合した。

追加ファイル `scripts/guard-contract.js` は `referenceChildren` のみをルール遷移として使う深さ3のOR/ANDオラクルを持つ。自分の手番は勝てる選択が一つあればよく、相手の手番は全応手で勝てることを要求する。合法手がない非終局を勝利扱いせず、深さ切れを永続的な安全や引き分けと判定しない。検査対象の `captureRoutes` や `forcedThreeAction` を正解判定に流用しない。

各局面で以下を照合する。

- 本体の全合法手と遷移が独立実装と一致すること。
- 両プレイヤーの得点可能な星の集合と、返された得点手の合法性・実際の得点。
- 3手以内の強制勝利の有無と、返された証明手。
- 全相手応手から求めた即負け回避可能手の集合と、retainの安全候補分類。
- 安全手がある場合、retainが危険手を残さないこと。3手必勝をすべて除外しないこと。
- 入力局面を変更しないこと。固定間隔で左右反転・180度回転・プレイヤー番号交換後も判定が一致すること。

## 固定した小盤面の全列挙

計画は `guard-contract-2026-10-24-plan.json`。3×2長方形は壁1/2個・星1/2個・目標2・両得点0/1の全組合せ。3×3正方形と中央欠損リングは壁1個・星1個・目標1。全てプレイヤーの位置・開始手番を入れ替え、壁・星が重ならず両者が少なくとも一方向へ動ける静的配置を列挙する。壁の添字は昇順配置に固定し、同じ物理配置の壁番号順列は重複させない。

|領域|局面|合法な初手遷移|即勝利あり|即勝利はなく3手必勝|3手必勝なし|安全/危険の選択がある局面|
|---|---:|---:|---:|---:|---:|---:|
|3×2・壁1/2個|7,392|13,696|2,368|440|4,584|736|
|3×3・壁1個|5,856|30,736|2,256|1,216|2,384|1,312|
|3×3中央欠損|3,040|9,584|992|336|1,712|464|
|計|16,288|54,016|5,616|1,992|8,680|2,512|

不一致0。得点経路の証明手16,928件と、381件の変換後局面も照合した。これらの件数は対局数ではなく、局面・遷移・証明手の検査数である。同一局面の再実行や変換を独立した勝率標本として数えない。

3×2には両者が幾何的には動けても、滑走後の閉じ込め禁止を満たす完全合法手がない静的配置352件が含まれる。今回、それらを勝利や引き分け扱いしていない。正式初期配置から到達するという証拠ではなく、本番の新しい不具合発見ともしていない。残りの星が目標達成に足りない静的配置も含む。初期局面からの合法対局分布ではなく、判定の境界条件を含む検査領域である。

## 保存済みBの17局面

別計画 `guard-contract-2026-10-24-archived-plan.json` で、既存 `reports/guard-study-2026-10-23/cases.json.gz` の17チェックポイント全件を、結果を見ずに対象とした。圧縮元のSHA256も固定。小盤面検査の後に追加した補足であり、未使用の独立対局とは扱わない。

17局面・合法初手1,285件・安全手1,000件・得点証明手6件が一致。安全/危険の選択を持つ局面は6件。全根手と全必要応手の独立判定では、この17局面に3手以内の強制勝利はなかった。これは勝利不能や最善手での敗北を意味しない。不一致0。

## 検証器自体の失敗検出

5件の回帰テストを追加した。協力的な勝ち経路と全応手に対する必勝を区別し、時間・深さ切れや非終局の合法手なしを誤って勝利にしない。さらに意図的に得点経路を消す、存在しない必勝を返す、安全手があるのに危険手をbeamへ戻す、という3種類の改変を注入し、それぞれ検査が失敗することを確認した。本体や保存済みAIを改変して検証してはいない。

これまでの保存局面中心の回帰に対し、16,288局面・381変換と17既存局面の全件再計算を、ハッシュ付きで繰り返せるようになった。品質検証範囲の拡張であり、プレイヤーへの新機能は追加していない。

## 再現方法

```sh
node --test tests/guard-contract.test.js
node --max-old-space-size=768 scripts/guard-contract.js --verify
node --max-old-space-size=768 scripts/guard-contract.js --archived --verify
```

全列挙は順序と判定結果のSHA256を保存結果と照合する。実行時間・Nodeバージョンは保存するが、再現一致の条件には含めない。生成時のローカル実行はNode v24.19.0/Linux x64、小盤面約3.25秒。CIではNode 22を使用する。通常CIへ追加するのは短い固定領域の再計算のみで、大量の新規対局生成は追加しない。

## 残る課題と採否

この範囲では判定器の修正は不要だった。追加した独立検証と回帰テストを採用候補として提出する。A〜Eの大盤面全局面、長期的な安全、最善手公平性、候補保持後の評価関数の良さ、AI間の総合強さ、人間の楽しさ・所要時間は今回の検証対象外。実機iPhoneの新しい確認もしていない。

次のゲーム性改善では、候補保持と評価関数を分けた同予算比較、Bの未使用局面、Dの位置偏り、A/C/Eの保存対局継続を引き継ぐ。小盤面の判定一致を理由に正式CPUや配置を採用しない。今回の新規初期対局0、継続0、勝率比較0。過去の対局台帳は変更しない。
