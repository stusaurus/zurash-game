# 新標準：独立seedの追加対局と得点・防御の局面監査

## 判断
既存ルールの**追加最適化が必要**。現行9×9・星9・先取4は試遊候補であり、面白さや公平性の認定ではない。今回、新ルールや正式盤面を変更しない。実際の人間による試遊は未実施。

## 追加対局
PR #50の予備実験にない4 seed（830041, 830252, 830463, 830674）。4盤面×2方策（greedy同士、random同士）×4 seed×先後2＝**新規64局**。最大96手、未決着は引き分けではない。同一条件のseedを対応させたが乱数消費は着手数等でずれる。物理的なコマ位置自体は変更せず、先手を切り替えた。`games.jsonl`に着手、初期条件、終局、seedを保存し、正式エンジンで64局再生。候補探索や最終評価のための十分な独立標本ではない。

9×9星9先取4の先手勝率は決着8局中3/8。独立二項標本と仮定したWilson 95%区間は約14〜69%だが、ペア化・同一盤面・棋譜重複の影響があるため厳密な実験単位として解釈しない。勝率や公平性の結論には不十分。先取5は先取4と星・壁・位置が同じで勝利条件だけ異なる。7星と9星先取4は2個の星の有無だけが異なる。7×7との違いは複数変数が同時に変わっており、原因を特定できない。小標本ゆえ中央値等の揺れも大きい。

初手では9×9星9先取4は両側62合法手・10停止地点。評価値が最高から50以内の15手は全て同じ停止地点。greedy採用初手は8局で2種類だが、これらの数は異なる作戦の優劣を証明しない。初手集中は評価関数や同点処理、盤面等を切り分ける必要がある。

## 具体的な得点か防御か
`node scripts/standard-tactics-audit.js` は保存されたgreedy棋譜を順に調べ、相手が次手で得点できる局面から、得点手と、相手の直後の全合法手で得点を防ぐ非得点手の組を最大3件抽出する。11局面を調査して3件を発見、棋譜の出現率推定ではない。`tactics.json`には初期盤面、履歴、局面、行動、応手と結果を保存する。

最初の例（seed 830041、先手0、6手終了後、1対1）。マス番号は左上0から右へ、1行9マス。

- 得点：壁27→28、コマ33から左へ滑り29の星を取り2対1。相手は壁移動を省略し78から上へ滑り51の星を取って2対2にできる。
- 防御：壁42→43、コマ33から下へ滑り69に停止。1対1のままだが、相手の次の合法手30通りを全列挙すると即得点は0通り。

これは「直後の得点を阻止する手」の存在証明であり、防御が得点より強い、将来の得点を保証する、または勝利につながることの証明ではない。相手のその後の壁操作による反撃は未評価。準備手の強制成功、逆転の因果、数手前の壁の寄与は未検証。

## 試遊手順
同じCPU難易度で入門7×7と試遊9×9星9先取4を、先後を入れ替えて各2局以上。可能なら2人対戦も同様に行う。各局の開始・終了時刻、迷った手番と理由、相手の予測、準備・妨害と結果、勝敗の理由、再戦意欲（5段階）、より面白い盤面と理由を記録。小学生には難しい用語を使わず「どこで迷った？」「思った通りになった？」と聞く。順序効果を避けるため、試遊者ごとに先に遊ぶ盤面を入れ替える。実施前に結果を記入しない。
