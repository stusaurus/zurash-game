# ズラッシュ！2人戦・公平性収束研究ログ（2026-10-18）

## 目標と採否
3つの既存7×7面を、先後の偏り・得点しない長期戦・展開の偏りを確認しながら改善する。
**現時点で正式認証された新配置は0面。現行本番の3面は変更しない。**

収束判定は、単純な勝率50%ではなく、同等AIの先後交替／ペアseedごとの区間／未決着／無得点20手以上の停滞を含める。
候補は探索用seedのみで比較して選別し、別の未使用seedを「holdout」と「validation」の2組に分けて判定する。
3政策（greedy、search、route）の両組で基準を満たした場合だけ計測上の収束とする。
計測上の収束でも、完全解析による最善手公平性や人間のゲーム体験を証明するものではない。

## 第1反復・実績（GitHub Actions）
旧手法（greedyだけで候補を選択、各面3反復・1反復最大10候補、holdout/validation各16ペア）：
- **追加対戦1,152局、約159.08秒**
- 3面とも **未収束、採用0**。結果は実際のGitHub Actionsログに記録。
- [Run 39118952613](https://github.com/stusaurus/zurash-game/actions/runs/39118952613)

候補を選択した後の最初の未使用seedブロック（各政策32局）：

| 面 | 星優先AI：先手/後手/未決着 | 通常探索AI | 新強AI（route） |
|---|---|---|---|
| はじまりの氷原 候補 | 11/21/0 | 21/9/2 | **27/5/0** |
| ふたつの谷 候補 | 24/8/0 | **5/25/2** | 16/11/5 |
| こおりの回廊 候補 | 16/16/0 | 11/20/1 | **8/22/2** |

**重要な発見：星優先AIだけで最適化すると、別のAI方針では極端な先後偏りが残る。**
また、標本は各条件32局と少ないため、点推定の増減だけで採否を判断しない。
上限120手の未決着は、ゲーム内ルール上の引き分けではない。

## 第2反復：学習時点から複数AIを用いる
上記の弱点を受けて次の手法に更新。
- greedy/search/route すべてを、候補のスクリーニングに利用。重み30%/30%/40%。
- 同seedの先後2局を丸ごと再抽出する**ペア単位ブートストラップ**で95%区間を算出。単純に各ゲーム独立とは扱わない。
- holdout/validationは学習用seedと別にし、両ブロックの全方針で条件が揃わない場合は正式採用しない。
- 収束判定の精度条件として、各比較について**決着100局以上**を要求。16ペア程度の予備試験は構造欠陥の発見用であり、判定を「合格」とはしない。
- 合格条件：先手率45～55%、対応95%区間40～60%以内、未決着率10%以下、無得点20手以上35%以下、合法手ゼロ0。
- 探索は有限回数で実行し、時間・試行上限で満たせない場合は `NOT_CERTIFIED` を出す。合格扱いにして本番変更しない。

## その後の反復で検証すること
1. 現行3面と改善候補を同じAI方針・同じ未使用seedで比較する。
2. ルール/CPU/画像は維持し、星と壁の初期位置だけを小さく変えて比較する。
3. 初手の実質最善手集中、星取得までの手数、長期戦を悪化させない。
4. 合格した配置が現れた場合も独立の強AI・人間対人間で追試してからDraft PRに掲載する。
5. 条件を満たさない候補は何面試しても公開しない。3・4人戦へは進まない。

## 再実行
```sh
npm ci
ROUNDS=3 VARIANTS=10 TRAIN_PAIRS=8 SEARCH_TRAIN_PAIRS=3 ROUTE_TRAIN_PAIRS=3 HOLDOUT_PAIRS=16 MAX_PLIES=120 npm run quality:converge
```

フルの統計的収束判定には `HOLDOUT_PAIRS` を十分増やし（決着が100局以上になる設定）、別の未使用seedで追試する。
実験結果は `reports/stage-convergence.json` に出力され、ワークフローからartifactとして取得できる。
