# ズラッシュ！CPU回転対称性の独立診断（2026-10-18）

## 目的
2人戦の公平性を大量シミュレーションで認定する前に、実験AIが
**盤面180度回転＋プレイヤー交換に対して同じ戦略的判断をするか**を分離して確認する。
本番の「つよい」CPUは変更しない。試験専用に `sym-route` を追加した。

## 最初の判断のずれ
固定seedで到達した66局面を回転させ、旧 `chooseRoute` の出力を比較した結果、
**66局面中8局面で異なる行動**を選んだ（58/66一致）。
回転対称な合法手を持っていても、列挙順や同点処理などでCPU選択は必ずしも対応しない。

`sym-route` は今手番のプレイヤーが常に同じ正規化座標から判断し、
入力局面・履歴・出力の手を回転変換する実験専用方針。
`tests/symmetry-ai.test.js` で途中状態・局面履歴を含めて回転等価性をテストし成功。

## 注意すべき解釈
- 最初の66局面は選択された再現サンプルであり、AI全般における判断不一致率を推定するための無作為標本ではない。
- 各80局は限られた標本であり、`sym-route` にすると「はじまりの氷原」で先後の点推定が均衡に近づいたが、区間幅が大きく正式認証条件には不足。
- 谷では未決着率が**14/80→22/80**へ悪化。回廊でも先後偏り・停滞は解消しない。**製品CPUへの採用は見送る**。
- 比較した `route/sym-route` と `sym-route/sym-route` は、この実装では全対局が同一になった。なぜなら手番0の `sym-route` は元の `route` と同じ行動で、違いがあるのは手番1だけだから。従って独立した「旧対新CPU実力比較」とみなしてはならない。
- AIの回転等価性とゲームそのものの先手公平性は別概念。人間の公平性・楽しさを証明しない。

## 実装・再現
- `scripts/symmetry-policy.js`: 実験専用CPU
- `scripts/check-ai-rotation.js`: 回転診断の固定局面サンプル
- `tests/symmetry-ai.test.js`: 回転後の判断が一致する回帰テスト
- `.github/workflows/ai-symmetry.yml`: 比較のJSON・合法手再生アーティファクトを保存

```sh
node scripts/check-ai-rotation.js
PAIRS=40 MAX_PLIES=120 LAYOUT_IDS=0,1,2 MATCHUPS='route/route,sym-route/sym-route,route/sym-route' RNG_MODE=worker SEED_OFFSET=910001 REPORT=reports/ai-symmetry-comparison.json npm run quality:study
npm run quality:replay -- reports/ai-symmetry-comparison.json
```

## 次に優先する条件
- 谷・回廊ではCPUの回転正規化だけでは改善がないため、初期星・壁・開始位置を含む配置に原因があるかを探索。
- 合格基準は変更しない。先後、未決着、無得点停滞、複数AI方針の全てに裏付けが必要。
- 現行の3面・CPU・ルール・画像・本番サイトはそのまま維持し、合格前の公開は行わない。
