# ズラッシュ！ 第1版 品質・バランス評価

正式仕様のルールを維持し、2人用Webゲームとして実装。旧リポジトリへの書き込みなし。

## 検証条件

- 自動対戦600局：3配置 × 5組合せ × 20 seed × 先後入替2局。
- 壁移動の比較120局：同じ星優先評価で、壁も使う側と毎回壁移動を省略する側を比較。
- seed：`701 + pair * 131 + layout * 977`。pairは0〜19。先後で同じseedを使用。
- 各ペアでコマの開始位置を固定し、開始プレイヤーを入れ替えた。3配置は180度対称。
- 先読み：2手先、候補上位6手、弱い候補の応手探索は早期終了。Web版は上位8手で、同一設定ではない。
- 星優先：得点差・各星までの滑走距離・次手での取得機会を評価。両方とも反復への減点あり。
- 160手で計測終了。**ゲーム内の引き分けルールではない**。
- 平均手数は計測上限で止めた対戦も160手として含む。1手＝片方の壁操作＋滑走。
- 同じseedの先後ペアは独立標本ではない。勝率はこのAIと配置に限る観測値。
- 再現：`PAIRS=20 npm run balance`、`node scripts/ablation.js`。

## 評価と最小限の判断

- **標準は「はじまりの氷原」を採用**。初手で星を取れる合法手は両者とも0。
  先読み同士は先手18勝・後手21勝・上限1局。決着39局中の先手勝率46.2%。
  上限率2.5%、平均25手。少数標本なので「公平」とは断定しない。
- 「ふたつの谷」は両者とも初手の取得手が1つあり、先読み同士の上限率が20%。
  選択可能な参考配置として残すが、標準には採用しない。
- 「こおりの回廊」は先読み同士で先手19勝・後手21勝・上限0局。
  最大150手なので長期戦リスクは残る。
- ランダム同士では全3配置で約半数が上限に達した。星を停止位置に合わせる目的を理解しない行動では長期化しやすい。
- **壁移動には実質的な価値がある**。同じ星優先評価で壁を使う側が120局すべて勝利。
  これは「毎回壁を動かせば正解」の証明ではない。比較側は省略だけに制限された弱い方策である。
- 標準の先読み同士では壁を省略する手も23手選択された。
  省略が役立つ局面は観測されたが、人間にとっての判断の深さは対人テストが必要。
- 先読み 対 星優先では先読み側が全配置合計93/120局勝利（77.5%）。
  相手の応手を読む価値を支持するが、ビーム幅・評価関数・同点処理の影響も含む。
- 星の奪い合い：共通の可視5個を取り合う構造で、相手の次手の星取得をCPU評価に反映。
  接戦率や人間の「取り合っている」感覚は未定量化。
- 初手の強制勝ち、全局面での到達可能性、無限対局の不存在は未証明。
- 先手補正・新得点・カード・ターン制限は追加しない。まず人間の実戦で原因を見極める。
- 目標10〜20分、勝敗への納得感、負けた悔しさ、再戦意欲は未評価。
  AIの手数や勝率で人間の楽しさを証明しない。

## 動作検証

- Nodeのルール・不変条件テスト：9件成功。
  4方向、壁・盤端・相手停止、通過と停止の違い、3個勝利、壁移動制約、閉じ込め防止、
  手番・状態不変性、即勝利を選ぶCPU、合法手ランダム連続実行、壁の個体IDに依存しない反復判定。
- 最初のCI：Chromium/WebKitの6実操作テスト成功。
  壁選択・移動・省略・滑走・星取得・勝利・再戦・戻る・CPU応答・CPU待ち中リセットを再現。
- 最終CI：同じ操作に加え、モバイルWebKit（390×844、DPR3、タッチ有効）を追加。
  CPU応答と戻る・リセットをtapで実行。最終版の9テストがすべて成功。
  [最終実装のCI結果](https://github.com/stusaurus/zurash-game/actions/runs/39096420824)（ルール9件・ブラウザ9件）。
- 320 / 390 / 768 / 1200pxで横はみ出しなし、49マス、盤の正方形、各マスの正方形、
  戻るボタンの折り返しなしをアサートし、スクリーンショットを保存。
  最終レイアウトの [390px画面](preview-mobile-390.png) と [320px画面](preview-mobile-320.png) を保存。
- 目視で見つけた320pxタイトル折り返しと行の高さの不揃いを修正。
- 実行中の操作ではJavaScriptのpageerrorが0件であることを検査。
- iPhone実機のSafari・低電力時の性能・VoiceOver・実物ボードの検証は未実施。
