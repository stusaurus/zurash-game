# TACTICS 5分モード — 実装前の検証ゲート (2026-10-20)

## 現行コードの事実
- engine.js は SIZE=7、step() にも7が直書き。盤面拡張は SIZE 変更だけでは成立しない。
- 3配置はいずれも7×7・壁8個・星5個・先取3個。
- 既存 layout-lab.js は候補を試すが、7×7固定、星5個、壁8個、先取3個を前提とする。
- 既存監査では強CPU同士の長期停滞が確認されている。人間の対戦時間は未測定。

## 開発原則
1. 既存7×7と現行ルールを変更しない。実験は独立スクリプト・ブランチで実施。
2. まず TACTICS 候補を同じ7×7で探し、盤面拡張はその後の対照実験とする。
3. 壁移動・滑走・星取得という基本操作は維持。新能力・カード・強制終了は加えない。
4. カレーあり／なしは、具体的な仕様がコード上で確定するまで評価対象の定義を保留し、推測で実装しない。

## 実験設計
- ベースライン：現行3配置。
- 候補：180度回転対称の星／壁配置を探索。壁数8個・星5個を固定した比較を最初に実施。
- 同じseed、先手交代、複数方策（greedy/search/strong）で比較。
- 主指標：決着率、未決着率、決着局の手数中央値・P90、初得点までの手数、先手勝率と95%区間。
- 副指標：得点なし20手以上の割合、初手の多様性、得点差、逆転勝利率、合法手ゼロ、不正状態。
- 未決着を引き分けと誤記せず、勝率の分母・打切り上限を明示する。
- 探索seedと採用判定用の保留seedを分ける。候補採用は複数方策・保留seedで再検証する。
- 対局時間5分はAI手数だけで確定しない。人間の操作・思考時間を測る。

## 人間テスト（各候補）
- 小学生・大人それぞれで初見説明後の理解度、実対局時間、迷った局面、負けた理由の説明、再戦意欲を記録。
- 目標時間：TACTICS 5分前後。人間テスト前は「5分モード完成」と表記しない。
- 先後差は単一AIの数値だけで合格としない。

## 次の実装タスク
1. 実験用シミュレーションの出力を再生検証できるようにする。
2. 7×7候補配置を現行3配置と比較し、保留seedで再試験する。
3. 採用可能な候補がなければ無理に採用せず、壁数・星配置の探索幅を広げる。
4. 盤面拡張する場合は engine / UI / AI / テストの座標依存を列挙し、全て可変サイズ化してから試験する。
5. 人間テストを通過した候補のみ製品のモード選択画面へ追加する。
