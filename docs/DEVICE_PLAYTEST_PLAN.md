公開版の「ふつう」は内部 `search`、「つよい」は `strong`。研究版の「ふつう」は `greedy`、「つよい」は `search`、「恐つよ」は `strong`。名前だけで同じCPUとして比較しない。研究版では「やさしい」=`random`、「ふつう」=`greedy`、「つよい」=`search`、「恐つよ」=`strong`、「学習」=`learning`。初期設定は研究版の「ふつう」。学習開始前は `greedy` と同じ選択で、保存済み学習の有無を必ず記録する。

研究版を試すには、試遊者が操作できるPC上の別ディレクトリに取得し、表示されたSHAが上記と同じことを確認する。次は**ローカルネットワーク内の試遊用サーバーの例**で、GitHub Pagesや本番への公開ではない。共有先のネットワークを選び、試遊後はCtrl+Cで停止する。

```sh
git clone https://github.com/stusaurus/zurash-game.git zurash-playtest
cd zurash-playtest
git fetch origin feat/five-mode-learning-ui
git switch --detach f708cb39e87aa8412fa5b18eecb8627dc0c620a6
git rev-parse HEAD
python3 -m http.server 8080 --bind 0.0.0.0
```

同一LANに接続した実機のSafariで `http://<PCのLAN内IPv4>:8080/` を開く。PC・実機の接続、ファイアウォール、端末間通信の許可は未検証であり、アクセスできなければその時点で「未実施」とする。クラウド作業環境が実機から直接到達できるとは限らない。LAN用URLは試遊端末だけに共有し、実際に届いたURLとSHAを記録する。公開版とLAN版は通常別のブラウザ保存領域を使う。保存データをリセットする際は、対象端末・サイトを確認する。

- [ ] 動き自動／ON／OFFで壁とトリケンの移動、踏ん張り・停止・勝敗表示が見えるか確認。設定切替で対戦が勝手に初期化されないか確認。
- [ ] トリケンが途中を滑って見えるか、端や壁で停止するか、誤タップ・盤外にはみ出し・スクロールとの干渉を記録。Eは特に小さなマスと横スクロールを確認。

### CPU・学習データ

- [ ] 各盤面で「やさしい／ふつう／つよい／恐つよ／学習」を選択でき、CPU先手・人間先手で1手以上進むか。CPUの待ち時間と中断・回復表示を記録。
- [ ] 学習対戦は「戻る」が無効。設定取消では対局が維持され、確定済みの人間の手だけが学習対象になるか。
- [ ] 学習対戦の終局を1回記録し、表示の勝敗・対局数・学習手数と再読み込み後の値を照合。再戦は別対局として数え、途中破棄は数えない。
- [ ] 未決着の明示記録とデータ消去の確認ダイアログを、取消・確定の両方で確認。未決着は勝敗や自動引き分けと区別する。記録済みデータの消去は試遊者の了承を得る。
- [ ] 保存不能の警告が出た場合、表示とその後の操作を記録。保存不能時に再読み込み後の保持・重複排除は保証されない。

## 人間試遊の進め方

1. まず公開7×7と研究版7×7で操作に慣れ、同一内部レベルによる差を確認する。説明の有無と対戦版を記録。
2. 研究版6盤面をすべて試す。2人対戦を含め、5 CPUレベル×先手／後手の条件を分担する。完全な組合せは6盤面×5難度×先後＝60条件で、各条件に記録が付くまでは未実施とする。無理に一人に60局を課さず、複数人・複数日に分けてよい。
3. 各盤面・難度で人間先手／CPU先手の両方を試し、端末・経験・学習データ状態を記録する。**CPU対戦では人間はP1、CPUはP2に固定**される。先手変更は物理位置の交換ではない。物理位置を比べる際は2人対戦で同じ参加者がP1・P2を交換し、先手も独立して変える。
4. 新規参加者と経験者の記録を分け、同じ人・同じ条件の連続対局を独立標本とみなさない。少数試遊の勝率だけで公平性やCPU難易度の序列を証明しない。
5. 対局時間は開始から勝敗確定まで実測し、休憩を別記録する。5〜10分は目標であり、AIの手数から人間の時間を推定しない。途中終了は打切り・未決着として保持し、引き分けと扱わない。
6. 参加者には名前ではなく任意の識別子を使用し、経験、分かりやすさ、選択肢、攻防、逆転、勝敗の納得感、再戦意欲を記録。自由記述は任意にする。

## 次のゲームバランス検証の優先順位

試遊の阻害要因（操作不能、異常終了、長いCPU停止、保存不良）を最優先で記録し、その後は以下を並行して扱う。優先度は[PR #20のモード別整理](https://github.com/stusaurus/zurash-game/blob/dcc511a5b82d5ac1cb7099c99fae107f03758fe8/docs/MODE_READINESS.md)の研究条件に基づく仮説で、人間試遊による確定結果ではない。

1. **B・C・Dの先後と物理位置**：Bの先攻傾向、C・Dの位置差について先手と席を分け、対人で攻防の選択肢・逆転・納得感も見る。CPU先後のみでは位置差を切り分けられない。
2. **A・Eの時間と停滞**：5〜10分の目標に対する実測時間、無得点期間、反復、EのCPU待ち・小画面操作を記録する。
3. **全盤面・全難度の操作と面白さ**：難度の体感、再戦意欲と敗因の理解を記録。未試験の盤面・条件は未実施のままにし、同時に公平性評価も継続する。

正式な合格基準や採否判断は、人間試遊の実測を踏まえて提案し、次の検証の前に固定する。この資料だけで完成・公平性を認定しない。
