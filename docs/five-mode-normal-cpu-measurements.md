# 検証用A〜E「ふつう」CPUの初期局面計測

基点: PR #38 `45033201f33b2da2bcf96e243bdcf0526626e4ed`。盤面の公平性・人間の所要時間を評価する試験ではない。

2026-10-27、Node 24.19.0、各初期盤面の両手番で `search`・seed 100〜102を各3回実行。合法手集合との一致を確認。時間は `choose` の壁時計ms（JIT・共有ホスト・計測誤差を含む）。

同一ホストのiPhone相当WebKitでは実Workerの生成・初期化・メッセージ往復込みの各1回は、先手/後手それぞれ A 88/31、B 31/43、C 91/173、D 176/37、E 261/65 ms。全て合法手を返した。Chromiumの同一計測は A 54/40、B 30/36、C 44/36、D 20/22、E 30/50 ms。各回は別Workerのwall-clockであり、先後のCPU強度比較ではない。

この小標本は全局面・低速端末・実機iPhoneの上限や分布を保証しない。WebKitはiPhoneエミュレーションであり、実機確認は未実施。研究盤面は正式採用ではなく、`strong`の可変盤面探索は対象外。初期局面の全10条件が6秒未満であり、今回の検証用「ふつう」の限定有効化を判断した。

Worker失敗・6秒時間切れ時はスキップ可能な合法滑走を優先し、不可能な場合だけ有限の壁候補を確認する。探索評価をメインスレッドでは実行せず、画面に思考中断を通知する。失敗Workerからの遅延応答はepoch変更で拒否する。7×7の既存探索・fallback方針は維持する。
