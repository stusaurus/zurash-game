# ズラッシュ！第25段階 — スマホ盤面タップ中心UI・品質確認

対象：Draft PR #49（`design/zurash-mobile-ice-integration`）。
正式採用済みの氷の背景、ロゴ、トリケンの画像、実際の盤面・ルール・CPUの処理を維持する。

## 操作体系

| 状況 | スマホ | デスクトップ |
|---|---|---|
| 壁移動 | 壁をタップ → 選択した移動先をタップ | 同じ |
| 壁を動かさない | 「そのまま滑る」 | 「壁を動かさずに滑る」 |
| 滑走 | 発光する実停止マスをタップ（`.cell.stop[data-slide-dir]`） | 既存の方向キー、または停止マス |
| 戻る | 「戻る」 | 既存の「戻る」 |
| 勝利・再戦 | 実ゲームの判定と結果画面 | 同じ |

スマホでは既存の `#directions` を表示しない。ゲームの `slideOptions()` と `finishSlide()` は変更しない。
`data-slide-dir` は停止マスを作った元の合法手から得る表示用属性であり、手を計算し直さない。

## 見た目

- 十字キーの場所をなくし、得点・手番の小型表示と「そのまま滑る」「戻る」だけのコンパクトな台座。
- 発光する停止マス（青緑）と壁の移動先（暖色）を区別する。スターの絵は隠さない。
- 滑走の経路には薄い氷の光を表示し、着地には短い光の輪。入力を取らない `aria-hidden` レイヤーのみ。
- 星の取得時は既存の星の演出を維持し、得点欄を短く光らせる。新アイテム、効果のあるゲーム要素を追加しない。
- 「動き OFF」とOSの動き軽減設定を尊重し、明示的な「動き ON」は既存の仕様を尊重する。

## 検証

- スマホ幅320、375、390、430で、横はみ出し、操作ボタン44px、得点表示、Safe Areaを確認。
- A〜Eの全モードで `#skip` → 合法な停止マスのタップ → 次手番に進むことを確認する。
- スマホでは `#directions` が表示されず、デスクトップでは引き続き機能することを確認する。
- 壁の移動、Undo、CPU、勝利、再戦、星の取得を既存テストで維持する。
- 発光の停止マスは実際に `button` であり、キーボードで操作できることを確認する。
- `pointerdown` のみ、ドラッグして離すだけでは手番が進まないことを確認する。
- `prefers-reduced-motion` では氷の装飾エフェクトを作らないことを確認する。
- 実機iPhone Safariのプレイと視認性は、自動テストとは別に確認が必要。

## リリース

総合Game quality、スマホUI、滑走演出、勝敗演出の各CIが成功するまで正式採用しない。
実機で盤面と残りの操作が直感的に使えるか確認した後に承認判断。
PRはDraftのまま維持し、mainへのマージ・本番公開はしない。

## 第30段階：星獲得時の手元スコア反応

星を獲得した直後、画面上部の公式スコアカードには既存の `just-scored` が付き、黄色の光で得点を示す。スマホでは盤面下の小型スコア表示を見る場合があるため、このイベントを表示専用 `src/mobile-command-feedback.js` でミラーする。スコアの数値を独自計算せず、公式カードの文字とクラスだけを読み取る。

CPU対戦では `runCPU()` が同期的にスコア欄を再描画するため、公式カードへの得点演出クラスをCPU描画の後に付ける。AIの探索、手番、得点計算には一切手を加えない。

テストは、公式「ふたつの谷」盤面でエンジンの合法手を列挙し、初手で実際に星を取得する。ローカル対戦で得点数0→1／得点側の発光／Undo復帰を検証し、CPU対戦では思考欄への描画切り替え後も得点発光イベントが観測できることを検証する。動き軽減モードや手動OFFでは発光アニメーションを抑止する。
