# 学習CPU内部基盤（UI未接続）

PR #18の `src/learning.js` と `chooseLearning` を移植。人間の手を、盤面の幅・高さ・勝利点数・マッチポイントと、滑走方向・壁移動の有無・得点の有無の16特徴に集計する。少なくとも当該コンテキストに8サンプルがあるとき、PR #18と同様にgreedyの同点候補だけを重み付きの相手応手評価で選ぶ。異なる盤面のサンプルでは学習を発動しない。未学習時はgreedyそのものを呼び、乱数の消費も一致する。

## 次工程での接続契約

- メインスレッドで `openLearning(localStorage)` を呼び、`model` のコピーを `level: 'learning'` とともにWorkerへ渡す。localStorageへアクセスできない場合も一時モデルで継続し、`warning` で通知できる。データをネットワークに送信しない。
- 対局ごとに新しい一意IDを作り、`beginMatch({id, mode:'cpu', human:0})` を一度だけ呼ぶ。同一対局で呼び直す必要がある場合は同じIDを使う。`mode:'local'` は記録対象外。
- 確定した人間の手について `observe(着手前状態, 合法手)` を呼ぶ。戻る時には、その手が取り消された分だけ `undo()` を呼ぶ。対局途中の記録は保存されない。
- 終局した場合だけ `finish(終局状態)` を呼ぶ。未決着を利用者が明示的に確定した場合のみ `finish(状態, {unresolved:true})` を使う。単にページを閉じる場合や結果を記録しないリセットは `discard()` する。
- 同じIDの記録は保存データに保持し、再読み込み後も重複を拒否する。記録IDが1万件に達した場合は記録せず警告する。保存できないときはメモリ上で継続するため、再読み込み後の重複防止は保証できない。破損データは勝手に上書きせず、明示的な `reset()` で削除できる。`reset()` は既存セッションも無効化する。
- 現時点ではゲーム画面・操作・Worker送信側は未接続であり、自動学習や対局結果の記録は起きない。UI統合時に対局終了、再戦、戻る、取消、明示的な未決着確定との接続を検証する。
